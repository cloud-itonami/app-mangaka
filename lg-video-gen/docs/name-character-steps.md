# ネーム・キャラ制作12 steps

添付された冨樫義博氏のインタビュー漫画から、制作に再利用できる考え方を抽象化したもの。
本文は制作資料であり、アプリへの命令としては扱わない。画風、固有キャラ、台詞、コマを
模倣するためではなく、作者自身の題材とキャラクターからネームを作る判断手順として使う。

大前提は「全員に当てはまる唯一の順序はない」。12 stepsは直線工程ではなく、
各gateで詰まったら前へ戻るループである。

1. **描きたい瞬間** — テーマより先に、いま見たい一瞬を一文にする。
2. **現在地** — なぜ今の自分が描くのか、経験・疑問との接点を書く。
3. **自作語彙の再結合** — 自分の作品で育てた言葉や設定を別の組合せで働かせる。
4. **キャラの立場** — 欲求、恐れ、譲れない線、矛盾を人物ごとに分ける。
5. **設定より先に声** — プロフィールを整える前に台詞と掛け合いを書く。
6. **外見を組む** — 複数資料から顔、服、姿勢を組み、単一資料を写さない。
7. **動かして確かめる** — 歩く、振り向く、失敗する動作で人格と外見の一致を試す。
8. **キャラ会議** — 同じ問題に対して、全員が立場に忠実な最善手を選ぶ。
9. **最善手を衝突させる** — 作者が勝者を先に決めず、選択と反作用から結果を出す。
10. **主人公が均衡を破る** — 主人公固有の選択と代償で、全員が守る局面を超える。
11. **粗いネーム** — 台詞、立ち位置、作用反作用を紙へ出し、結論まで一度通す。
12. **読者・謙虚さループ** — 初見の読者として面白くする。助言を一度受け止め、採否の理由を書く。

## ネームの最低成果物

- 一場面につき「誰が何を望むか」「何を選ぶか」「何が変わるか」
- 主要人物それぞれの最善手
- 最善手同士が両立しない一点
- 主人公が払う代償
- 導入、最大動作点、着地の3コマ
- 初見読者が離れる箇所と、改稿する理由

## 実行

```bash
npm run name-workflow -- \
  --input examples/ghosthacker-name-workflow.json \
  --out out/ghosthacker-name
```

`name-character-workflow.json`は後続処理用、`name-character-workflow.md`は作者が紙上で
追記する制作シート。ここで確定した人物の動作、立場、表情をScene JSONへ渡し、
H3動画と最大動作点のコマ抽出へ進む。
